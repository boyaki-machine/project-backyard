# 自律実行の使い方

**チケット1件を、エージェントに計画から完成まで任せる。** PM（あなた）は、計画の承認・確認への回答・最後の受け入れだけを行う。
本書は**使う人の手順**である。仕組みの設計は `design/Delegation.md`、画面の設計は `design/GuiDesign.md` 5.5「自律実行」。

| 役 | 誰が | 何をする |
|---|---|---|
| **PM** | あなた（画面） | 自律実行を始める・計画を承認する・ユーザ確認待ちに答える・根を受け入れる |
| **main** | エージェント1 | ヒアリング・計画・分解・起票・実装・報告 |
| **評価** | エージェント2（**main とは別に登録したもの**） | main の計画と成果を、独立に合否判定する |

**PB はエージェントを自分では起動しない。** 2つのエージェントのセッションは、あなたが端末で開いて一言を送る。
以後、エージェントは PB を待ち受けて（`pb_wait`）動き続け、あなたへの用事は画面の「ユーザ確認待ち」に届く。

---

## 1. 準備（初回だけ）

### 1.1 エージェントを2つ用意する

- **`/me/agents` でエージェントを登録し、トークンを発行する**（手順は PB の文書「エージェントの参画情報」）
- **main と評価は別のエージェントにする。** 同じものを選ぶと、始めるときに拒まれる
- **評価のエージェントには、トークンの発行時に「追加の権限」で `delegation.evaluate` を足す。** 無いと評価を書けない
- **始める人（あなた）は `delegation.manage` を持つこと**（プロジェクト管理者に配られている）
- **このセッションで別の作業をしているエージェントを main にしない。** 作業の記録（`pb_start_work`）は、
  1つのエージェントにつき1プロジェクトで同時に1件しか開けない
- 種類（Claude Code / Codex など）は問わない。**評価を別の種類にすると独立性が高い**

### 1.2 トークンをセッションごとに分ける

接続設定にはトークンの**変数名**だけが書いてある。**セッションを開くシェルで、その変数に別々の値を入れる。**

| 種類 | 変数 | 開き方（作業フォルダで） |
|---|---|---|
| Claude Code | `PB_TOKEN`（`.mcp.json` が読む） | `PB_TOKEN=<main 用のトークン> claude` |
| Codex | 接続設定の `--token-env` / `bearer_token_env_var` が指す名前（例：`PB_TOKEN_CODEX_1`） | その変数を入れたシェルから起動する |

- `~/.zshrc` に入れた `PB_TOKEN` は、**どのセッションでも同じ値**になる。2つ目の Claude Code は、上の形で値を上書きして開く
- 開いたら、エージェントに「PB の自分の名前を教えて」と頼み、`pb_get_project` などの応答で**意図した名前のエージェントで繋がっているか**を見る

### 1.3 ツールの承認を減らす

**エージェントは、待ち受け（`pb_wait`）を何十回も呼ぶ。** 呼ぶたびに承認を求められると、あなたが端末に張り付くことになる。

| 種類 | すること |
|---|---|
| Claude Code | 権限のモードを auto か acceptEdits にする。PB のツールは `.claude/settings.local.json` の `allow` に `mcp__pb__pb_wait` などを足してもよい |
| Codex | `.codex/config.toml` の `[mcp_servers.pb.tools.pb_wait]` に `approval_mode = "auto"` を足す。評価が書く `pb_submit_evaluation` / `pb_post_note` も、任せるなら同じく足す |

**書き込み系の自動承認は、あなたの判断で行う。** PB は段階ごとの操作を API で拒むので、計画の承認前の起票などは許可しても通らない。

## 2. 始める（画面）

1. 任せたいチケットを開く。**親を持たないか、エピックの直下のチケット**であること
2. **説明と完了条件を、そのまま目的として読まれる前提で見直す。** 自律実行に「目的」の欄は無い。触ってよい場所はスコープ境界の欄
3. 実行モードで **「自律実行」** を選ぶ。下に項目が開く

| 項目 | 入れるもの |
|---|---|
| main エージェント / 評価エージェント | 1.1 で用意した2つ |
| 子チケットの数・階層・期日 | main が起票できる上限。超える起票は拒まれ、一時停止になる |
| 評価のやり直し | 不合格のまま往復してよい回数（既定3） |
| 止まる条件 | 「◯◯が起きたとき」と**事象で**書く。当たると main はあなたに確認する |
| 指標と要約の周期 | 任意。周期ごとに要約が届く |

4. **「自律実行を始める」** を押す。状態が「計画中」になる

---

## 3. エージェントを呼ぶ

画面の **「エージェントの呼び方」→「表示する」** に、送る一言が出る。コピーして各セッションへ送る。

| 種類 | main | 評価 |
|---|---|---|
| Claude Code | `/pb-delegate-main <番号>` | `/pb-delegate-eval <番号>` |
| 他（Codex など） | 「PB のチケット <番号> を自律実行の main として進めて」 | 「PB のチケット <番号> を評価エージェントとして見て」 |

- **評価も同時に呼んでおく。** 評価は計画が出るまで待ち受ける
- **最初も、止まった後の呼び直しも同じ一言である。** エージェントは手元の引き継ぎファイル（`.pb-local/delegation/`）と PB から続きを読む

---

## 4. 回っている間にすること

**画面のチケットに「ユーザ確認待ち」が出たら、あなたの番である。** それ以外はエージェントに任せてよい。

| 届くもの | すること |
|---|---|
| ヒアリング | main が目的を掘り下げる問い。答える（何回か続く） |
| 計画の承認 | 評価が合格した版にだけ「承認」が押せる。却下は理由を書く（main が直して出し直す） |
| 範囲の外・後戻りできない操作（マージ・push など）・憲章の変更 | 選択肢と推奨が付いてくる。選んで答える |
| 周期の要約 | 読んで、指標の値を入れて答える。答えるまで main は止まる |

- **いま何をしているか**は「エージェントステイタス」の1行で見る。経緯は「計画と評価の履歴を見る」
- **止めたいとき**は「一時停止」。再開は「再開…」（制約を直せる）。止めている間、エージェントは書き込みを拒まれ、手を止める
- エージェントの**セッションを閉じても壊れない。** 同じ一言で呼び直せば続きから再開する

---

## 5. 終える

- **受け入れ**：main が根に完了レポートを出し、評価が合格したら、成果を確かめて**あなたが根を完了にする**。子の完了も人が行う
- **やめる**：「自律実行をやめる…」で、戻す実行モードを選ぶ。子チケットは残り、回答していないユーザ確認待ちは取り下げられる
- 終了を知ったエージェントは、手元の引き継ぎファイルを消して止まる。セッションは閉じてよい

---

## 6. つまずいたら

| 起きたこと | 見るところ |
|---|---|
| 「このプロジェクトで使えるエージェントではありません」 | そのエージェントが有効で、別のプロジェクト専用になっていないか（`/me/agents`） |
| 評価エージェントの評価が拒まれる | トークンに `delegation.evaluate` があるか（1.1）。無ければ再発行で足す |
| 「main と evaluator には別のエージェントを指定してください」 | 1.1 |
| 「自律実行にできるのは、親を持たないか、エピックの直下のチケットだけです」 | 2 の 1。親を付け替えるか、親側で始める |
| エージェントが動かない | セッションで待ち受け（`pb_wait`）がツールの承認待ちで止まっていないか（1.3） |
| 意図しない名前で記録されている | セッションのトークン（1.2） |
| エージェントが「止められた」と言って止まった | 一時停止か、制約を超えた。画面の「ユーザ確認待ち」と制約を見て、再開する |
