**MCP 層は REST を内部の HTTP 呼び出しで叩く**（同じプロセス内で `/api/v1` を持つルータへ渡す）。
8.1 の「権限判定・検証は REST 層に置く」を**経路として強制する**ためで、`RequireProjectPermission`

解決した文脈が残っていると、内側のルータが消費済みのパスで照合し、405 や 403 になる
（結合テストで実際に踏んだ。`internal/mcp/rest.go` にコメントで残した）。

**エンドポイントの必要権限は `agent.run`。** 0019 がこのキーを「MCP から走らせてよい」と
定めており、`RequireProjectPermission` を1本だけ掛けている。**`/mcp` の木ごとミドルウェアで
包まない**——包むと `/mcp` 配下の未知のパスまで 401 になり、404 であるべきものが変わる。

**Cookie では通さない**（Bearer だけ）。CSRF の検証を持たない `POST` を増やさないためで、
**手順26 の write 系が入る前に閉じておく**必要がある。
