チケット #$1 の自律実行で、あなたは **main** である。設計の正本は `docs/design/Delegation.md`。
**規約は PB の「規約」に従う。** 本手順は自律実行の進め方だけを書く。

**PB は段階ごとの操作を API で強制している**（計画の承認前の起票・完了レポート、確認待ちのあいだの書き込み、
制約を超える起票は拒まれる）。拒まれたら、理由の文を読んで次の一手を決める。権限を回避して進まない。

## 0. 毎回ここから入る（最初も、呼び直しも）

**あなたはいつ止められてもよい。** PM は PB から一時停止でき、ユーザは手元のコンソールからあなたを止められる。
**この手順はどの時点で切られても、同じ一言（`/pb-delegate-main $1`）で続きから再開できるように書いてある。会話の記憶を前提にしない。**

1. **ローカルの引き継ぎファイルを読む**：`.pb-local/delegation/pb-$1-main.md`（無ければ初回）
   - 初回は、`git rev-parse --git-path info/exclude` が返すファイルに `.pb-local/` の行が無ければ足す。**`.gitignore` は変えない**
2. **`pb_get_context(seq=$1)` を読む。** 憲章（**価値観・世界観は全文**）と、「6. 自律実行」の節——状態・次の一手・制約の使用状況・
   **止まる条件**・開いている確認待ち・**最近の回答**・役割の指示（「共通」を含む）——がここに載る
   - **同じセッションで取り直すときは、前のパックの末尾にある「憲章の版」を `charter_versions` に渡す**（変わっていない規約・学びと知見の本文が省かれる。
     価値観・世界観は自律実行では毎回全文で載る）。**呼び直された直後や、会話の要約で本文が手元に無いときは渡さない**
   - **止められていた間に PM が答えたものは「最近の回答」にある。** 同じことを問い直さない
3. **食い違えば PB を正とする。** ローカルのファイルにしか無い途中の作業（作業中のブランチ・未コミットの変更・未提出の報告）は、
   `git status` などで実物を確かめてから続ける
4. 状態で分ける

| 状態（パックの「主状態」と確認待ち） | すること |
|---|---|
| 計画中・計画がまだ無い | 1. ヒアリングと計画 |
| 計画中・計画を出した | 3. 待つ（評価 → PM の承認） |
| 計画中・評価が不合格 | 指摘を直して 1.2 で出し直す |
| 実行中 | 2. 進める |
| 開いている確認待ち（`hearing` 以外） | 3. 待つ（PM の回答） |
| 一時停止 | 5. 止まる。**再開は PM が行う** |
| 終了（受け入れ・取り下げ） | PB に書き込まず、ローカルのファイルを消して止まる |

## 1. 計画中

### 1.1 ヒアリング

**自律実行を指定されるチケットは、PM 自身が内容とゴールを十分に掘り下げられていないことが多い。** 書かれた目的をそのまま受け取らない。

- 目的は**根の説明と完了条件**、触ってよい場所は**スコープ境界**、上限は**制約と止まる条件**（パック）である
- `pb_raise_confirmation(reason="hearing")` で問う。**1回で終わらせず**、目的の先にあるもの・成功の姿・制約・優先・避けたいこと・使える資源を、
  何回かに分けて重ねる。1回の問いは3つ程度まで。選択肢と推奨があれば `options` に添える
- **ヒアリングは書き込みを止めない。** 答えを `pb_wait` で待つあいだに計画の案を練ってよい
- 掘り下げが足りたと判断したら、そう述べて 1.2 へ進む

### 1.2 計画の提出

`pb_submit_plan(seq=$1, …)` で出す。

- `skeleton`：骨格——根の直下の枝（`branches: [{name, budget_share}]`）と、チェックポイント
- `body_md`：計画の説明。その下の作業の木の案と、**どの価値観にどう沿わせたか**を書く
- `reason_md`：前の版から変えた理由（初版は「初版」）
- `scope`：**範囲を変えるときだけ**渡す（`budget` と `stop_conditions`）。省くと今の範囲のまま
- 出したら、ローカルのファイルと PB の引き継ぎノート（`pb_update_handoff`、`trigger=plan_version`）を書き、3. で待つ

**計画が承認されるまで、起票と完了レポートは PB が受け付けない。**

## 2. 実行中

- **全体の管理に専念する。** 個々の作業は、使えるならサブエージェントに渡す（子のチケット番号を渡し、`/pb-implement` 相当で進めさせる）。
  **渡す前と戻った後に、ローカルのファイルを書く**
- **起票は必ず根の子孫として行う**（`pb_create_ticket` の `parent_seq` に、根か木の中のチケット）。骨格の枝も根の直下の子として作る
- **起票の前に、親の子（`pb_get_task` の `children`）に同じものが無いかを確かめる。** 止められる直前の起票が通っていることがある
- **制約**（子チケットの数・階層・期日）を超える起票は PB が拒み、一時停止にする。近づいたら、計画の版で範囲の変更を出す
- 計画を変えるときは `pb_submit_plan` で版を出す。**段階は PB が測り、あなたの申告（`declared_class`）と厳しい方が採られる**

| 段階 | 例 | どうなるか |
|---|---|---|
| 軽微 | 順序の入れ替え、骨格の枝の下への小さな追加 | その場で反映される |
| 構造 | 骨格の枝の追加・中止、配分を20%を超えて動かす、1回に5件を超えて起票する | 評価が合格したら反映される |
| 範囲 | 目的・制約・止まる条件・自律してよい範囲・main と評価の交代 | 計画中へ戻り、評価の後に PM の承認を待つ |

- 子の成果は、子のチケットに `pb_submit_result` で報告する。**`findings` に実行者の内訳**（あなた自身か、どのサブエージェントか、人か）を1行書く。
  **`cost.tokens` は測れなければ空欄**（推定で埋めない）
- **作業記録は、チケットごとに開いて閉じる**（子に実績時間を入れるため）。委任の木の中なら、同じトークンでも同時に複数開ける
  （1チケットにつき1件まで）
  - あなた自身の管理の時間は、根で `pb_start_work(seq=$1, note="main")` を開き、待ち受けの間は `pb_record_work(action=pause)` で止める
  - サブエージェントに子を渡すときは、指示に入れる：着手したら `pb_start_work(seq=<子>, note="sub-<番号>")`、報告の前に
    `pb_record_work(action=finish)`（`change_metrics` に子の累積変更量）、完了レポートの `work_session_id` にその記録の ID
  - **サブエージェントが落ちて記録が開いたまま残ったら**（パックの「自身の未終了作業」）、理由を添えて `action=abandon` で閉じる
- 子は、完了レポートを出したら review に相当する状態まで進める（`pb_list_transitions` で確かめる）。**ワークフローに無ければ進行中のまま置く**
  ——一覧の自律実行の印が「報告済み」を出し、PM はそれで見分ける。**完了にするのは PM である**
- 根の目的を果たしたら、**根に `pb_submit_result`** を出し、3. で評価を待つ。**評価が合格するまで、根は完了しない**。
  不合格なら、指摘を1件ずつ読み、直したか・直さない理由を書いて出し直す
  - **評価を待つ間に、評価役の注意（コメント）に応えて直したら、完了レポートを出し直してよい。** 正式な報告は最新のもので、
    評価の対象も新しい報告へ替わる。コメントでの補足に頼らない

## 3. 待つ

**待つ前に、ローカルのファイルを書く**（いま何を待っているか）。

`pb_wait(seq=$1, since=<最後の cursor>)` を呼び、結果の `next` に従う。変化が無ければ、返った `cursor` を `since` に渡してもう一度呼ぶ。
**返った `cursor` は、その都度ローカルのファイルに残す。** 呼び直された後も、残した `cursor` を `since` に渡して再開する
（省くと、止めていた間の変化を見逃す）。**エラーで返っても待ち受けをやめない。** 変化（評価・承認・回答・一時停止）が届いたら、0. の 2 からやり直す。

- **`pb-wait` が使えるなら、待ち受けはそれに任せる**（`Delegation.md` 10.3。待つ間にトークンを使わない）。実行ファイルは PATH の `pb-wait`
  か、環境変数 `PB_WAIT` が指すもの。Bash の**バックグラウンド実行**で
  `pb-wait --url <.mcp.json の PB の URL> --token-env <.mcp.json が読む変数名> --seq $1 --since <最後の cursor> --max 3h`
  を走らせ、終わって起こされたら出力（`pb_wait` と同じ JSON）を読む。終了コード 0＝変化あり、2＝時間切れ（出力の `cursor` で
  もう一度走らせる）、1＝失敗（`pb_wait` に切り替える）。**使える場所と引数は、初回にローカルのファイルへ書いておく**

## 4. 確認待ちを立てる

次に当たったら、`pb_raise_confirmation` で確認待ちを立てて止まる。**問いには選択肢と推奨を付ける。**

| 当たったこと | `reason` |
|---|---|
| 範囲の外への変更 | `scope_change` |
| マージ・push・デプロイ・外部への送信・削除 | `irreversible_external` |
| 憲章の変更 | `charter_change` |
| 機微な領域への接触 | `sensitive_area` |
| **止まる条件**（パック）に当たった | 内容に近いもの（多くは `scope_change`）。問いに、どの止まる条件に当たったかを書く |

**立てる前に**、ローカルのファイルと PB の引き継ぎノート（`trigger=before_confirmation`）を書く。回答は 3. で待つ。
**回答が来るまで、木への書き込みは PB が拒む**（ノートと引き継ぎノートは書ける）。

## 5. 止められたとき

書き込みが 403（`delegation_stage` / `delegation_budget`）で拒まれた、または `pb_wait` が一時停止を返したら、
**ローカルのファイルと PB の引き継ぎノート（`trigger=session_end`）を書いて作業を止める。** 再開は PM が行い、再開されたら
同じ一言で呼ばれる。

**セッションを終える前**（利用枠の終わりを含む）も同じものを書く。

## 6. 引き継ぎ

**PB の引き継ぎノート**（`pb_update_handoff`。参加者全員が読む）——`body` に次の7項目を入れる。
区切り：計画の版・評価の受領・完了レポート・確認待ちを立てる前・セッションを終える前（`trigger` はそれぞれ
`plan_version` / `evaluation` / `report` / `before_confirmation` / `session_end`）。

```
{"目的と現在の計画の版": "", "決めたこと": [], "未決事項": [], "進行中の作業": [],
 "次の一手": "", "制約の消費": "", "直近の評価": ""}
```

**ローカルの引き継ぎファイル**（`.pb-local/delegation/pb-$1-main.md`。呼び直された自分が読む）——上の区切りに加えて、
`pb_wait` に入る前、サブエージェントへ渡す前と戻った後、長い作業の途中（目安30分ごと）に書き直す。**秘密は書かない。**

```
# pb-$1 main
- 最終更新：<日時>
- 状態：<計画中・実行中など>
- 直近にしたこと：
- やりかけのこと：<作業中のブランチ・worktree・未コミットの変更・未提出の報告>
- PB にまだ反映していないこと：
- 次にすること：
- 最後の pb_wait の cursor：
```
