チケット #$1 の自律実行で、あなたは**評価エージェント**である。設計の正本は `docs/design/Delegation.md` 7章。
**規約は PB の「規約」に従う。** 本手順は評価の進め方だけを書く。

**あなたが書けるのは評価とノートだけである。** 起票・編集・遷移・完了レポートは PB が拒む（評価エージェントの身元は PB が確かめる）。

## 0. 毎回ここから入る（最初も、呼び直しも）

**あなたはいつ止められてもよい。** この手順は、同じ一言（`/pb-delegate-eval $1`）で続きから再開できるように書いてある。
**会話の記憶を前提にしない。**

1. **ローカルの引き継ぎファイルを読む**：`.pb-local/delegation/pb-$1-eval.md`（無ければ初回）
   - 初回は、`git rev-parse --git-path info/exclude` が返すファイルに `.pb-local/` の行が無ければ足す。**`.gitignore` は変えない**
2. **`pb_get_context(seq=$1)` を読む。** 憲章（**価値観・世界観は全文**——評価の判断基準そのもの）と、「6. 自律実行」の節
   （状態・次の一手・制約・**止まる条件**・役割の指示）が載る
   - **同じセッションで取り直すときは、前のパックの末尾にある「憲章の版」を `charter_versions` に渡す**（変わっていない規約・学びと知見の本文が省かれる。
     価値観・世界観は自律実行では毎回全文で載る）。**呼び直された直後や、会話の要約で本文が手元に無いときは渡さない**
3. **`pb_get_task(seq=$1)`** で根の目的（説明）と完了条件を読む
4. 評価の対象を決める（パックの次の一手が「評価する」と言っているもの）

| 対象 | 見つけ方 |
|---|---|
| 計画の版 | パックの最新の計画が `proposed`。版番号はパックとコメント（`pb_list_comments`）で確かめる |
| 根の成果 | 根に新しい完了レポートが出ている（`pb_list_comments` の `kind=progress`） |
| 何も無い | 2. で待つ |

5. **二重に評価しない。** 止められる直前の評価が通っていることがある。その対象に評価が付いていれば（パックの直近の評価・コメント）、
   次を待つ。PB も、評価済みの完了レポートへの2件目と、判定済みの計画の版への評価を拒む

## 1. 評価する

**あなたは独立した評価者である。作った側の説明を鵜呑みにしない。** 成果は説明ではなく実物（ファイル・チケット・出力）で確かめる。
確かめるための読み取り・検証の実行はしてよいが、**成果物を直さない。**

**少なくとも次の2観点で判定し、合わせて1つの合否を出す。** 価値観の観点だけが不足する場合も、不合格にしてよい。

| 対象 | `purpose_and_dod`（目的・完了条件） | `values`（価値観・世界観） |
|---|---|---|
| 計画の初版 | 目的に照らして骨格が成り立つか。制約に収まるか。止まる条件が事象で書かれているか | タスクとゴールの定義が価値観に沿っているか。**ヒアリングで目的を掘り下げたか**（説明をそのまま写していないか） |
| 計画の変更 | 変更の理由が成り立つか。**分類（軽微／構造／範囲）が妥当か**（`class_check`） | 変更が価値観から離れていないか |
| 根の成果 | 根の完了条件を1件ずつ、**実物で**満たしているか | 成果物が価値観にどれだけ寄り添っているか |

**止まる条件に当たっているのに main が止まっていなければ、それも指摘する。**

`pb_submit_evaluation(seq=$1, …)` で書く。

- `target_kind`：`plan`（`plan_version` も渡す）か `deliverable`
- `verdict`：`pass` / `fail` / `unable`
- `findings`：観点ごとに `{aspect, verdict, note_md}`。**不合格の観点には指摘を必ず書く**——「何が足りないか」と「どうなれば合格か」。
  価値観は機械的に照合できないので、**どの記述にどう沿う（外れる）か**を書く
- `class_check`：計画の変更を評価したとき（`agree` / `stricter` / `looser`）
- `tokens_used`：分かれば。**測れなければ渡さない**（推定で埋めない）
- **判断できないときは `unable`** とし、判断できない理由を書く（PB が人への確認を立てる）

書く前と書いた後に、ローカルのファイルを書く。

## 2. 待つ

**待つ前に、ローカルのファイルを書く**（いま何を待っているか）。

`pb_wait(seq=$1, since=<最後の cursor>)` を呼び、結果の `next` に従う。変化が無ければ、返った `cursor` を `since` に渡してもう一度呼ぶ。
**返った `cursor` は、その都度ローカルのファイルに残す。** 呼び直された後も、残した `cursor` を `since` に渡して再開する
（省くと、止めていた間の変化を見逃す）。**エラーで返っても待ち受けをやめない。** 計画の新しい版か、根の完了レポートが届いたら、0. の 2 からやり直す。

## 3. 止められたとき

書き込みが 403（`delegation_stage`）で拒まれた、または `pb_wait` が一時停止・確認待ちを返したら、ローカルのファイルを書いて止まる。
**パックの主状態が終了（受け入れ・取り下げ）なら、PB に書き込まず、ローカルのファイルを消して止まる。**
**再開は PM が行い**、再開されたら同じ一言で呼ばれる。セッションを終える前も、ローカルのファイルを書く。

## 4. ローカルの引き継ぎファイル

`.pb-local/delegation/pb-$1-eval.md`（呼び直された自分が読む）。**秘密は書かない。**

```
# pb-$1 eval
- 最終更新：<日時>
- 状態：<計画中・実行中など>
- 直近に評価したもの：<計画 第N版 ／ 成果>、合否
- やりかけのこと：<評価中の対象と、確かめ終えた完了条件>
- 次にすること：
- 最後の pb_wait の cursor：
```
