## TLS 証明書と接続方式

通常は生成された設定の **HTTPS 直接接続** を使います。PB の証明書が OS に信頼されていることが
条件です。自己署名または社内 CA の場合も、TLS 検証を無効化しないでください。

1. 証明書の発行元 CA を OS の信頼ストアへ登録します（macOS はキーチェーンアクセスで対象 CA を
   「常に信頼」、Windows は証明書マネージャーの「信頼されたルート証明機関」、Linux はディストリ
   ビューションの CA ストア）。登録前に CA の指紋を PB 管理者から照合してください。
2. {{.ClientDisplayName}} / VS Code を完全に終了して再起動します。
3. 不要になったら、**同じ CA 証明書だけ**を信頼ストアから削除します。PB 本体の公開証明書や
   組織で必要な CA を削除しないでください。

信頼ストアを変更できない環境では、PB リリースに同梱される `pb-mcp-bridge` をローカルの PATH に
置き、画面の「ローカル stdio ブリッジを使う」を選び直して設定をダウンロードします。ブリッジは
ローカルの stdio だけを使い、待受ポートを開きません。CA PEM を個人用の安全な場所に保存し、次を
設定します。

```
export PB_MCP_CA_FILE='/安全な場所/your-pb-ca.pem'
```

この変数を設定すると、ブリッジだけが OS の既定信頼ストアに加えてその CA を信頼します。
ブリッジの削除時は `[mcp_servers.pb]` と配下の tool 節を削除し、`pb-mcp-bridge`、CA PEM、
`PB_MCP_CA_FILE` の設定を削除してから {{.ClientDisplayName}} を再起動します。
トークンを不要にする場合は PB 画面で再発行またはエージェントを削除して失効させます。

## 繋がらないとき

| 症状 | 見るところ |
|---|---|
| ツールが1つも見えない | 設定が読まれていません。**そのフォルダが信頼済みか**を見てください。開き直しも要ります |
| `401` | 環境変数が空か、トークンが失効しています。**新しいシェルで開き直したか**も見てください |
| `404` | URL のプロジェクトと、トークンのプロジェクトが食い違っています |
| `403` | トークンのスコープか、所有者であるあなたの権限が足りません |
