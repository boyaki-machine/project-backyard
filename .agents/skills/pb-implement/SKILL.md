# PBチケット実装手順

ユーザーからPBのチケット番号を指定されたときは、以下の順序で進める。チケット番号が無い場合は、勝手にチケットを選ばず確認する。

## 1. 契約を取得する

- `pb_get_task` でチケット本文、種別、状態、DoD、実行モード、Readiness、スコープ境界を取得する。
- `execution_mode` が `human_only` なら実装せず、理由を報告して終了する。
- `readiness` が `red` なら不足点を示し、実装へ進むか利用者に確認する。
- 担当が自分の所有者でない、または担当が無い場合は実装せず利用者に伝える。

## 2. 前提を取得する

- `pb_get_context` でスコープ、実行前提、憲章、依存・関連チケットを取得する。
- このセッションで憲章を全文確認済みなら、その文書の版を `charter_versions` に渡す。本文が手元に無ければ渡さない。
- 不足する設計・規約がある場合は、`pb_list_docs` で目次を確認し、`pb_get_doc` で必要な文書または章だけを読む。
- プロジェクトの経緯、設計、チケットの意図を推測で補わない。

## 3. 方針を確認する

- チケット本文、DoD、スコープ、前提に不明点や矛盾があれば、実装前に利用者へ質問する。
- 変更ファイル、実装方針、影響範囲、検証方法を提示し、承認を得てからコードを変更する。
- 設計に無い判断、設計変更、依存追加、スコープ外変更が必要になった場合は、実装を止めて相談する。
- チケットが大きすぎる場合は、分割案を提示して利用者の判断を得る。自分でチケットを束ねない。

## 4. 着手する

- 承認後に `pb_transition_task` で `in_progress` へ遷移する。遷移できない場合は権限を回避せず報告する。
- `develop` と `main` では作業しない。チケット番号を含むfeature/fix/docsブランチを、プロジェクト規約に従って作成する。
- チケット作業でworktreeが必要な場合は作成し、完了後に規約どおり後始末する。
- `develop` へのマージ、`main` へのマージ、push、ブランチ削除は、完了時に利用者へ提案し、明示的な承認を得るまで実行しない。
- バージョン管理がある場合は、マージ前に種別に応じた `make bump-minor`、`make bump-build`、または `make bump-major` を実行する。マージ後に `make version-check` を実行する。
- 他のエージェントの差分を戻したり上書きしたりしない。
- Claude側の `LEARNINGS.md`、`.mcp.json`、`.claude/` 配下は変更しない。

## 5. 実装する

- `scope.allow` と `scope.deny` を守り、許可された範囲だけを変更する。
- 範囲外の変更が必要になったら、実装せず利用者に相談する。
- 無関係なリファクタリングや、ついでの修正を行わない。
- 重要な判断、設計との対応、途中で判明した事実は必要に応じて `pb_post_note` で記録する。
- 個人情報、秘密、端末固有の絶対パスをGit管理下のファイルやPBの共有記録へ書かない。

## 6. 検証する

- DoDの各項目を一つずつ検証し、結果と証跡を整理する。
- 変更範囲に対応する最も狭いテスト、lint、型チェック、ビルド、実機確認を優先する。
- 実サーバを検証する場合は、自分が起動したサーバへ要求が届いていることを確認する。
- 人間の確認が必要なDoDは、未完了として明示する。
- 検証が失敗したら、実装と検証の両方を確認する。検証対象が自分の変更であることを確かめる。

## 7. 結果を報告する

- `pb_submit_result` で成果物、DoDごとの判定と証跡、判明した事実、失敗した試行、コスト、`knowledge_impact` を構造化して報告する。
- `unsatisfied_dod` が返った場合は、内容を確認して必要な修正・再検証・再提出を行う。
- `pb_submit_result` は盤面の完了状態を変更しないことを前提に扱う。
- チケットをクローズしない。完了判定とクローズは人間が行う。

## 8. 知識を還流する

- 次に同じ領域を扱う参加者に有用な規約、設計上の注意、失敗事例があれば `pb_post_note` に残す。
- 憲章や設計文書を更新すべきだと考えても、指示なしに `pb_put_doc` を呼ばない。必要なら提案して利用者の判断を得る。
- セッション終了時、進め方の教訓だけを `LEARNINGS_CODEX.md` に追記する。チケット本文、設計、進捗、秘密は記録しない。

## 禁止事項

- 担当や権限を回避して作業を進めない。
- スコープ境界外のファイルを独断で変更しない。
- チケットをクローズしない。
- 指示されていない憲章・設計文書を更新しない。
- Claude側のローカル環境ファイルを変更しない。
